# Demo Scenario

## 데모 전 준비

1. PostgreSQL과 NestJS 서버를 실행합니다.
2. Next.js 클라이언트를 실행합니다.
3. Kakao 및 공공데이터 API 키가 환경변수에 설정됐는지 확인합니다.
4. 브라우저의 위치 권한을 허용합니다.

## 3분 시연 흐름

### 1. 현재 위치 기반 추천

- 첫 화면에서 현재 위치를 가져옵니다.
- 현재 기온과 날씨 상태가 표시되는지 확인합니다.
- 주변 식당이 지도 마커와 하단 목록에 점수순으로 나타나는 것을 보여줍니다.

설명 포인트: 위치, 날씨, 시간대, 거리를 서버에 전달해 한 번에 추천 결과를 계산합니다.

### 2. 추천 근거 확인

- 상위 식당의 적합도 점수와 추천 이유를 확인합니다.
- 비가 오는 날이라면 국물·전류, 더운 날이라면 냉면·빙수 관련 식당이 가점을 받는 로직을 설명합니다.

설명 포인트: 규칙 기반 추천을 사용해 결과의 이유를 사용자에게 바로 제시합니다.

### 3. 지도 탐색과 필터

- 음식 카테고리를 선택해 결과를 좁힙니다.
- 지도를 다른 지역으로 이동한 뒤 `이 위치에서 재검색`을 선택합니다.
- 현재 위치 버튼으로 원래 위치에 돌아옵니다.

설명 포인트: 지도 중심과 사용자 위치를 분리해 사용자가 다른 동네도 자연스럽게 탐색할 수 있습니다.

### 4. 식당 상세 정보

- 지도 마커 또는 목록에서 식당을 선택합니다.
- 상세 패널에서 주소, 전화번호, 영업시간, 메뉴와 사진을 확인합니다.

설명 포인트: 상세 데이터는 필요한 시점에 조회하고 서버에 캐시해 외부 요청을 줄입니다.

### 5. 로그인과 예약

- 로그인 후 식당 상세 패널에서 날짜·시간과 인원을 선택합니다.
- 예약을 생성하고 `내 예약` 화면에서 저장 결과를 확인합니다.

설명 포인트: 예약과 프로필 API는 JWT Guard로 보호되며 사용자별 데이터만 조회합니다.

## 위치 권한이 거부된 경우

기본 좌표인 서울시청 주변으로 식당을 조회합니다. 검색창에서 지역이나 장소를 입력하면 다른 위치로 시연할 수 있습니다.

## 데모 종료 시 강조할 내용

- 날씨를 단순 표시 정보가 아닌 식당 추천의 입력값으로 사용했습니다.
- 점수와 이유를 함께 제공해 추천 결과를 설명할 수 있습니다.
- 지도 탐색부터 상세 확인, 예약까지 하나의 사용자 흐름으로 연결했습니다.
