# Recommendation Logic

## 목표

추천 결과가 단순히 가까운 식당 목록에 머물지 않고, 사용자가 "왜 지금 이 식당이 어울리는지" 이해할 수 있도록 규칙 기반 점수와 설명을 함께 제공합니다.

## 입력값

| 값 | 의미 |
| --- | --- |
| `lat`, `lon` | 검색 중심 좌표 |
| `radius` | 검색 반경(km) |
| `sky` | 하늘 상태 코드 |
| `pty` | 강수 형태 코드 |
| `temp` | 현재 기온 |
| `category` | 선택한 음식 카테고리 |
| `timeOfDay` | `morning`, `afternoon`, `evening` |

## 태그 생성

Kakao가 제공하는 장소명과 카테고리 문자열을 분석해 식당에 다음과 같은 태그를 부여합니다.

- `RAINY_FOOD`, `WARM_SOUP`: 국밥, 찌개, 전골, 라멘 등
- `HOT_WEATHER`, `COLD_FOOD`: 빙수, 아이스크림, 냉면 등
- `SUNNY_FOOD`, `TERRACE`, `VIEW`: 브런치, 테라스, 루프탑 등
- `MORNING_FOOD`, `AFTERNOON_FOOD`, `EVENING_FOOD`: 시간대에 어울리는 업종과 메뉴

## 점수 계산

모든 식당은 50점에서 시작합니다.

| 조건 | 가중치 |
| --- | ---: |
| 비·눈과 `RAINY_FOOD` 일치 | +20 |
| 비·눈과 `WARM_SOUP` 일치 | +10 |
| 맑은 날과 `SUNNY_FOOD` 일치 | +15 |
| 맑은 날과 `TERRACE` 또는 `VIEW` 일치 | +15 |
| 추운 날과 따뜻한 음식 태그 일치 | +20 |
| 더운 날과 `HOT_WEATHER` 일치 | +15 |
| 더운 날과 `COLD_FOOD` 일치 | +15 |
| 현재 시간대 태그 일치 | +20 |
| 거리 가중치 | 최대 +20 |

거리 점수는 검색 중심에서 가까울수록 높아집니다.

```text
distanceScore = max(0, 1 - distance / radius) × 20
```

최종 점수는 0~100 범위로 제한하고, 검색 반경 밖의 식당은 제외한 뒤 높은 점수순으로 정렬합니다.

## 설명 가능한 결과

점수만 반환하지 않고 실제로 적용된 규칙을 `matchReason`으로 조합합니다.

```json
{
  "matchScore": 90,
  "matchReason": "비/눈 오는 날에 어울리는 음식, 뜨끈한 국물 생각나는 날"
}
```

## 규칙 기반 방식을 선택한 이유

- 초기 사용자 행동 데이터가 없어도 즉시 동작합니다.
- 추천 근거를 사용자에게 그대로 설명할 수 있습니다.
- 가중치를 코드에서 빠르게 검증하고 조정할 수 있습니다.
- 모델 학습·서빙 인프라 없이 서비스 핵심 가설을 확인할 수 있습니다.

## 확장 방향

식당 클릭 기록과 예약 전환 데이터가 충분히 쌓이면 규칙 점수를 기본값으로 유지하면서, 사용자별 선호 카테고리와 행동 가중치를 추가할 수 있습니다.
